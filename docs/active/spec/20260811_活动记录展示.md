## 1. 需求概述

在 Sedum 顶部主导航新增独立“活动记录”页面，展示 FatPet 上传到 snow-grass `activity_events` 数据域的应用名称、Bundle ID、新增文字和发生时间，并提供筛选、分页、刷新及隐私删除能力。

## 2. 范围

**In scope（本次做）**：

- Sedum 新增活动记录导航和响应式列表页面。
- 按关键词、应用、开始时间、结束时间筛选，服务端分页。
- 支持删除单条记录、删除当前时间范围内记录，并在危险操作前确认。
- 展示 30 天默认保留策略、脱敏说明、加载/空态/错误态。
- snow-grass Activity 领域新增向后兼容的分页查询和删除能力。

**Out of scope（本次不做）**：

- 不把 Activity 内容写入 Chat、Memory、Agent 或 Skill 上下文。
- 不展示窗口标题，不增加键盘采集范围或绕过 macOS 权限。
- 不实现云端账号、多用户隔离、导出文件和长期统计看板。

## 5. API 接口清单

### Activity 分页查询

- **路径**：`/api/v1/activity-events/page`
- **方法**：`GET`
- **用途**：为 Sedum 提供服务端筛选和分页；保留原 `/activity-events?limit=` 兼容 FatPet 与已有测试。
- **关键请求参数**：
  - `page`（integer，可选，默认 1）：页码。
  - `page_size`（integer，可选，默认 50，最大 200）：每页数量。
  - `query`（string，可选）：匹配文字、应用名称或 Bundle ID。
  - `bundle_id`（string，可选）：精确筛选应用。
  - `start`（ISO 8601 datetime，可选）：发生时间下界，包含边界。
  - `end`（ISO 8601 datetime，可选）：发生时间上界，包含边界。
- **关键响应字段**：
  - `items`（ActivityEventResponse[]）：当前页记录。
  - `total`（integer）：筛选后的总记录数。
  - `page`、`page_size`（integer）：当前分页信息。
- **数据来源**：本机 snow-grass Activity 领域扩展设计。

### 删除单条 Activity

- **路径**：`/api/v1/activity-events/{event_id}`
- **方法**：`DELETE`
- **用途**：删除用户明确选择的一条记录。
- **关键请求参数**：`event_id`（path string，必填）。
- **关键响应字段**：`deleted`（integer）：0 或 1。
- **数据来源**：本机 snow-grass Activity 领域扩展设计。

### 删除时间范围 Activity

- **路径**：`/api/v1/activity-events/range`
- **方法**：`DELETE`
- **用途**：删除筛选器当前起止时间范围内的记录。
- **关键请求参数**：
  - `start`（ISO 8601 datetime，必填）。
  - `end`（ISO 8601 datetime，必填）。
- **关键响应字段**：`deleted`（integer）：删除数量。
- **数据来源**：本机 snow-grass Activity 领域扩展设计。

## 8. 技术实施方案

### 8.1 架构决策

| 决策 | 选择 | 原因 | 放弃的方案 |
|------|------|------|-----------|
| 领域边界 | Sedum 只调用 Activity Router | 保持原始文字流水与 Chat/Memory/Agent 生命周期解耦 | 复用 Memory API，会污染检索语义 |
| 分页方式 | Activity 专用分页响应，原 GET 保持兼容 | Sedum 需要总数和稳定页码，同时不破坏现有客户端 | 修改原 GET 返回对象，会造成破坏性变更 |
| 筛选位置 | SQL 服务端筛选 | 30 天内记录仍可能很多，避免一次拉取 200 条后产生错误总数 | 纯前端筛选只覆盖已加载记录 |
| 页面状态 | React 本地 state + `snowGrassApi` | 项目没有全局状态库，模式与 TokenUsagePage 一致 | 新增 Redux 等依赖，成本过高 |
| 删除保护 | 明确范围 + 二次确认 | 避免无参数清空全部记录 | 提供“清空全部”快捷入口，风险过高 |

### 8.2 数据流

```text
FatPet ActivitySyncService
→ snow-grass /api/v1/activity-events/batch
→ snow_grass.activity.repository.ActivityRepository
→ activity_events
→ /api/v1/activity-events/page
→ src/api/snowGrassApi.js#listActivityEvents
→ src/page/activity/ActivityEventsPage.jsx
→ Sedum 活动记录 UI
```

删除链路：

```text
ActivityEventsPage#deleteEvent/deleteRange
→ snowGrassApi.deleteActivityEvent/deleteActivityRange
→ snow_grass.activity.router
→ ActivityService
→ ActivityRepository
→ activity_events
```

### 8.5 异常处理

| 场景 | 处理方式 | 涉及文件 |
|------|---------|---------|
| 接口请求失败 | 页面内展示错误和重试按钮，保留当前筛选 | `ActivityEventsPage.jsx` |
| 数据为空 | 区分“暂无记录”和“当前筛选无结果” | `ActivityEventsPage.jsx` |
| snow-grass 离线 | 显示无法连接后端，不清空上一次成功数据 | `snowGrassApi.js`、`ActivityEventsPage.jsx` |
| 起始时间晚于结束时间 | 前端禁用范围删除；后端返回 422 | Activity 页面与 `service.py` |
| 删除失败 | 保留当前列表并显示错误，不做乐观删除 | `ActivityEventsPage.jsx` |
| 敏感文字 | 入库阶段继续使用现有 `ActivitySecurity.sanitize` 脱敏 | snow-grass Activity 领域 |

## 9. 验收标准（AC）

### AC1：查看活动记录

- **Given**：snow-grass 中存在 FatPet 上传的 Activity 记录。
- **When**：用户进入 Sedum“活动记录”页面。
- **Then**：页面按发生时间倒序展示应用名称、Bundle ID、新增文字和本地时间，且不出现窗口标题。

### AC2：筛选与分页

- **Given**：Activity 记录超过 50 条且跨多个应用。
- **When**：用户输入关键词、选择应用或时间范围并翻页。
- **Then**：服务端返回匹配记录、准确总数和页码，每页不超过 50 条，筛选变化后回到第一页。

### AC3：隐私删除

- **Given**：列表中存在可删除记录或当前筛选设置了完整起止时间。
- **When**：用户确认删除单条或时间范围记录。
- **Then**：后端只删除明确目标，页面刷新并显示正确剩余总数；取消确认不产生删除。

### AC4：领域解耦

- **Given**：Activity 页面执行查询和删除。
- **When**：检查 snow-grass import 边界与数据库写入。
- **Then**：Activity 包不依赖 Chat、Memory、Agent 或 Pet，Activity 内容不会进入 AI 上下文。

### AC5：异常与响应式

- **Given**：后端离线、返回空数据或窗口宽度低于 760px。
- **When**：用户访问页面。
- **Then**：分别显示可重试错误、明确空态和可读卡片布局，主导航及操作仍可使用。
