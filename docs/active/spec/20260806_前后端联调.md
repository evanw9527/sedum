## 1. 需求概述

将 `sedum/src/page/agent/AgentPage.jsx` 从模拟交互改造为调用 `snow-grass` 真实 API，支持模型/Skill 选择、会话持久化、SSE 增量回答、执行轨迹、停止生成和错误反馈。

## 2. 范围

**In scope（本次做）**：

- Vite 开发代理与可配置 API Base URL。
- 模型、Skill、会话、消息和 SSE 前端客户端。
- 真实会话列表/历史加载、新对话和流式对话。
- 模型/Skill 选择、连接状态、错误状态和 AbortController 停止生成。
- 通过 Vite 代理进行前后端联合烟测。

**Out of scope（本次不做）**：

- WorkflowPage 后端化、Skill 编辑页、附件上传、身份鉴权、Markdown 富文本渲染。

## 5. API 接口清单

| 路径 | 方法 | 关键字段 | 用途 |
|------|------|---------|------|
| `/api/v1/health` | GET | `status` | 连接检查 |
| `/api/v1/models` | GET | `id,name,provider_name,available` | 模型选择 |
| `/api/v1/skills` | GET | `id,name,enabled,allowed_models` | Skill 选择 |
| `/api/v1/sessions` | GET/POST | `id,title,model_id,skill_id` | 会话列表/创建 |
| `/api/v1/sessions/{id}/messages` | GET | `id,role,content,model_id,skill_id` | 历史消息 |
| `/api/v1/sessions/{id}/messages/stream` | POST | `content,model_id,skill_id` | SSE Agent 运行 |

SSE 事件：`run.started`、`step.started`、`step.completed`、`message.delta`、`message.completed`、`run.failed`、`run.completed`。数据来源：snow-grass 当前代码查询。

## 8. 技术实施方案

### 8.1 架构决策

| 决策 | 选择 | 原因 | 放弃的方案 |
|------|------|------|-----------|
| 开发跨域 | Vite proxy `/api` | 本地 URL 稳定，不硬编码 localhost | 组件直接访问 8000 |
| SSE 请求 | `fetch` + ReadableStream | 支持 POST body 和 AbortController | EventSource（仅 GET） |
| 状态 | AgentPage React hooks | 页面级状态，不需要全局 Store | 新增 Redux |
| 会话创建 | 首次发送时惰性创建 | 新对话不产生空记录 | 点击新对话立即 POST |

### 8.2 数据流

```text
src/page/agent/AgentPage.jsx#sendMessage
  → src/api/snowGrassApi.js#createSession/streamMessage
  → Vite /api proxy
  → snow-grass /api/v1/sessions/{id}/messages/stream
  → SSE parser
  → AgentPage#handleStreamEvent
  → MessageTimeline
```

### 8.3 改动详情

- `snowGrassApi.js`：将 HTTP 错误 detail 归一化，实现跨 chunk 的 SSE block 解析。
- `AgentPage.jsx`：初始并行加载目录/会话，切换会话加载历史，发送时创建占位助手消息并按事件更新。
- `ChatComposer.jsx`：可用模型检查，Skill `auto` 映射为 `null`，busy 时发送按钮执行 abort。
- `MessageTimeline.jsx`：每个 step 使用稳定 id，支持 pending/error 消息。

### 8.4 状态管理

`AgentPage` 使用 `useState/useEffect/useRef` 管理 catalog、session、messages、busy、error 和 AbortController。异步切换通过 request id 防止旧响应覆盖新会话。

### 8.5 异常处理

| 场景 | 处理方式 | 涉及文件 |
|------|---------|---------|
| 后端未启动 | 顶部/侧边栏显示未连接，保留重试提示 | `AgentPage.jsx`、`ChatSidebar.jsx` |
| 无可用模型 | 禁止发送，明确提示需配置 Key | `ChatComposer.jsx` |
| SSE 中断/失败 | 占位消息转 error，释放 busy | `AgentPage.jsx` |
| 用户停止 | AbortController.abort，消息保留已接收文本 | `AgentPage.jsx` |

## 9. 验收标准（AC）

### AC1：目录与连接

- **Given**：snow-grass 在 8000 端口运行。
- **When**：打开 Vite 页面。
- **Then**：通过 `/api` 代理加载模型、Skill 和会话，页面显示已连接。

### AC2：会话与历史

- **Given**：已有后端会话。
- **When**：选择会话或在新对话首次发送。
- **Then**：加载真实历史，新会话按消息摘要创建并出现在侧边栏。

### AC3：流式轨迹

- **Given**：有可用模型 Provider。
- **When**：发送消息。
- **Then**：增量显示文本，展示 Skill 选择轨迹，完成后恢复输入。

### AC4：缺 Key 和错误

- **Given**：DeepSeek/GLM Key 未配置。
- **When**：目录返回 `available=false`。
- **Then**：模型标记未配置且发送被禁用，页面不崩溃。

### AC5：工程验证

- **Given**：两个工程依赖完整。
- **When**：运行 `pnpm lint`、`pnpm build` 和代理烟测。
- **Then**：全部通过，`http://localhost:5173/api/v1/health` 返回 snow-grass 健康状态。
